# Tailwind CSS for This Django Project

This existing Django project uses Tailwind CSS locally through the official Tailwind CLI. It does not create a new Django project and does not use the Tailwind CDN.

## Files

- `package.json` contains Tailwind CLI scripts and dev dependencies.
- `assets/css/input.css` is the Tailwind source file.
- `static/css/tailwind.generated.css` is generated by Tailwind and loaded by Django templates.
- `static/css/site.css` contains this project's existing handwritten CSS, Font Awesome font-face rules, and custom selectors.
- `templates/base.html` loads the generated Tailwind CSS and the project CSS for the public website.
- `templates/dashboard/base.html` loads the generated Tailwind CSS and the project CSS for the dashboard.
- `gcms_project/settings.py` already has Django static files configured with WhiteNoise and `CompressedManifestStaticFilesStorage`.

## Install

Install Node.js LTS first if `npm --version` does not work.

Run from the project root:

```bash
npm install
```

## Development

Run this in one terminal:

```bash
npm run dev:css
```

Run Django in another terminal:

```bash
python manage.py runserver
```

## Production Build

Build the CSS, then collect Django static files:

```bash
npm run build:css
python manage.py collectstatic --noinput
```

Deploy the collected `staticfiles/` directory with the Django app. WhiteNoise will serve compressed, hashed static assets in production.

## Editing Styles

Use Tailwind utility classes directly in Django templates where possible.

Keep project-specific component selectors, legacy layout rules, and Font Awesome rules in:

```text
static/css/site.css
```

Do not edit `static/css/tailwind.generated.css` by hand because it is overwritten by the Tailwind build.

## Dynamic Classes

Tailwind scans source files as text. Always keep full class names in templates.

Good:

```django
<div class="{% if message.tags == 'error' %}text-red-600{% else %}text-green-600{% endif %}">
```

Avoid:

```django
<div class="text-{{ color }}-600">
```

If a class is built dynamically and cannot be written fully in a template, safelist it in `assets/css/input.css` with `@source inline(...)`.
